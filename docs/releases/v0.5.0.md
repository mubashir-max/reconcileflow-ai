# ReconcileFlow AI v0.5.0 — Cloud Storage and File Lifecycle

Version 0.5 adds private, provider-independent cloud object storage and a complete tenant-safe file lifecycle to ReconcileFlow.

## Highlights

- Provider-independent storage contract with local and S3-compatible implementations
- Private AWS S3, Cloudflare R2, and MinIO support
- Bounded streaming uploads with generated tenant-scoped object keys
- Short-lived presigned POST uploads and GET downloads
- Direct-upload finalization with authoritative size, checksum, content-type, and structure validation
- Pending-file deletion with database consistency and storage-usage release
- Aged abandoned-upload cleanup with dry-run support
- Organization quotas and authoritative storage-usage accounting
- Read-only integrity verification for missing, mismatched, and abandoned objects
- Explicit bounded repair for usage counters and confirmed aged orphans
- SQLite, PostgreSQL, Docker Compose, MinIO, and Python 3.12/3.14 validation

## Upgrade and compatibility

- Python 3.12 or newer is required.
- Run `alembic upgrade head` before starting directly installed services.
- Docker Compose applies migrations before starting the API and worker.
- Existing proxied upload clients remain supported.
- Direct-upload clients must finalize uploaded objects before they become reconciliation source files.
- Newly created organizations receive the configured default storage quota; zero explicitly means unlimited.

## Operational defaults

- Local storage remains the default development provider.
- S3-compatible storage requires a private bucket and credentials supplied through environment variables or a secret manager.
- Presigned URLs expire after five minutes by default.
- Abandoned and integrity scans process bounded batches and apply an age grace period.
- Integrity verification is read-only unless `--repair` is explicitly supplied.

## Security and privacy

Buckets and objects remain private. Presigned URLs are temporary bearer capabilities and must not be logged, persisted, or cached. Credentials must never appear in endpoint URLs, source control, logs, or API responses. Public failures and operational reports exclude object keys, provider responses, filesystem paths, credentials, signed URLs, and file contents. Every file operation remains scoped to the authenticated organization.

## Current boundaries

Production bucket provisioning, credential rotation, provider billing, CDN delivery, malware scanning, browser interfaces, and mobile applications remain deployment or future-roadmap concerns.

All included financial datasets are synthetic and anonymized.
