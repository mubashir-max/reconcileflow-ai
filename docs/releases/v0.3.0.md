# ReconcileFlow AI v0.3.0 — Authentication and Multi-Tenancy

Version 0.3 turns the persistent reconciliation API into a secure organization-based, multi-user backend platform.

## Highlights

- Password registration with Argon2 hashing and normalized identities
- Signed short-lived access tokens and rotating refresh-token sessions
- Refresh-token reuse detection, logout, and account-wide session revocation
- Authenticated password changes with current-password verification
- Persistent failed-login protection with configurable temporary lockouts
- Organization profiles and multi-organization discovery
- Membership management with OWNER, ADMIN, ANALYST, and VIEWER roles
- Tenant-isolated runs, uploads, results, reconciliation audit data, and security events
- Append-only security auditing without passwords or raw token values
- SQLite, PostgreSQL, Docker, and Python 3.12/3.14 validation

## Upgrade and compatibility

- Python 3.12 or newer is required.
- Run `alembic upgrade head` before starting a directly installed API.
- Docker Compose applies all migrations before starting FastAPI.
- Configure a unique `RECONCILEFLOW_TOKEN_SIGNING_SECRET` of at least 32 characters outside local development.
- Existing v0.2 reconciliation data is assigned to the legacy organization during migration.

## Security defaults

- Access-token lifetime: 15 minutes
- Refresh-token lifetime: 30 days
- Login lockout threshold: 5 consecutive failures
- Login lockout duration: 15 minutes
- Passwords use the recommended Argon2 configuration
- Refresh tokens are stored only as SHA-256 hashes

## Current boundaries

Email verification, password-reset email delivery, Microsoft/Google OAuth, CAPTCHA, distributed rate limiting, background workers, cloud object storage, user interfaces, human approvals, and AI-assisted matching remain future work.

All included financial datasets are synthetic and anonymized.
