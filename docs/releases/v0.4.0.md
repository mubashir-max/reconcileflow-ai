# ReconcileFlow AI v0.4.0 — Background Processing and Job Management

Version 0.4 moves reconciliation execution out of API requests and into durable, independently operated background workers.

## Highlights

- Durable organization-scoped background jobs linked one-to-one with reconciliation runs
- Asynchronous execution through a standalone worker process
- Atomic job claiming with worker leases, heartbeats, and stale-job recovery
- Immediate and scheduled reconciliation execution
- Automatic retry backoff and controlled manual retry operations
- Cooperative cancellation for queued and running jobs
- Persisted execution deadlines with safe timeout failures
- LOW, NORMAL, and HIGH priorities with aging to prevent starvation
- Tenant-scoped job status, queue summaries, and lifecycle-event APIs
- Aggregate worker readiness without worker names, hostnames, process IDs, or connection data
- Configurable retention cleanup for terminal jobs and inactive worker records
- Ordered, append-only job events containing sanitized operational metadata only
- SQLite, PostgreSQL, Docker Compose, and Python 3.12/3.14 validation

## Upgrade and compatibility

- Python 3.12 or newer is required.
- Run `alembic upgrade head` before starting directly installed services.
- Docker Compose applies migrations before starting the API and worker.
- Start the worker with `python -m reconcileflow.worker` outside Docker.
- Existing synchronous API consumers must now treat execution as asynchronous: the execution endpoint returns HTTP `202 Accepted` with a background-job ID.
- Poll the job-status endpoint or inspect its lifecycle events before retrieving completed results.

## Operational defaults

- Jobs are created with NORMAL priority unless explicitly selected.
- Priority aging raises the effective priority of waiting work to prevent starvation.
- Job attempts use configurable timeouts and retry limits.
- Workers emit internal heartbeats while public health endpoints return aggregate counts only.
- Retention cleanup preserves reconciliation runs, source metadata, results, and reconciliation audit history.

## Security and privacy

Background-job responses and lifecycle events intentionally exclude credentials, tokens, raw exception text, worker identifiers, hostnames, process IDs, storage paths, database connection details, and source financial data. Every public lookup remains scoped to the authenticated organization.

## Current boundaries

Distributed message brokers, horizontal autoscaling, cloud object storage, user interfaces, email delivery, external OAuth providers, human approval workflows, and AI-assisted matching remain future work.

All included financial datasets are synthetic and anonymized.
