# ReconcileFlow AI v0.2.0 — API and Persistence

Version 0.2 turns the verified reconciliation core into a persistent, versioned backend service.

## Highlights

- FastAPI application with OpenAPI and interactive documentation
- Liveness and database-aware readiness endpoints
- SQLAlchemy persistence with explicit transaction boundaries
- PostgreSQL schema managed by Alembic migrations
- Reconciliation run creation, listing, and retrieval
- Secure CSV/XLSX upload with bounded size, validation, hashing, and safe storage keys
- Synchronous execution through the existing deterministic engine
- Persisted, paginated, and filterable reconciliation results
- Ordered reconciliation audit-event retrieval
- Docker Compose development environment for FastAPI and PostgreSQL
- Automated SQLite and PostgreSQL test coverage through GitHub Actions

## Upgrade and compatibility

- Python 3.12 or newer is required.
- Run `alembic upgrade head` before starting a non-containerized API.
- Docker Compose applies migrations automatically before starting FastAPI.
- SQLite remains supported for local/unit tests; PostgreSQL is the target service database.

## Current boundaries

Execution is synchronous. Authentication, tenant isolation, background queues, cloud object storage, user interfaces, human approvals, and AI-assisted matching remain future work.

All included datasets are synthetic and contain no real financial or personal data.
